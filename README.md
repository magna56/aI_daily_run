# AI Daily Learn

Daily 30-minute AI learning sessions — and the reader that makes them readable.

**Read them here:** https://theaicommit.com (mirrored at https://magna56.github.io/aI_daily_run/)

Sessions are generated by the `/ai-daily-learn-publish` Claude Code skill
(bundled in `.claude/skills/`) and pushed here automatically every day at 11:00.

## Layout

```
journal.md          # running index of every session
YYYY-MM-DD/         # one session — the source of truth, never generated from the site
  topic.md          # the technical writeup (~10 min read)
  visualize.html    # standalone interactive model of the core mechanism
  code_example.py   # runnable, pure Python, no API keys (~15 min)
  diagram.excalidraw# the visual
  articles.md       # 3-5 curated sources with summaries

index.html          # the reader (self-contained: CSS + JS inline, no CDN)
build.js            # session folders -> site/data/
lib/excalidraw-svg.js  # .excalidraw -> SVG, at build time
lib/runner.js       # runs each code_example.py, captures its output
```

A `-s2` suffix (`2026-08-03-s2`) means a second session on the same day.
`site/` is build output: not committed, published to Cloudflare Pages
(theaicommit.com, the primary host) and force-pushed to the `gh-pages` branch
(GitHub Pages, kept as a mirror).

## The reader

On the GitHub tree view a `.excalidraw` file is an unreadable JSON blob and a
`code_example.py` is something you have to clone before it teaches you anything.
The site fixes exactly that:

| On the tree view | In the reader |
|---|---|
| `.excalidraw` renders as raw JSON | Pre-rendered to SVG, with pan/zoom — original still downloadable |
| A mechanism is hard to feel from prose | Sandboxed interactive model with real controls and readouts |
| `code_example.py` is inert | Executed at build time, so its output sits beside the source |
| No index or search | Searchable, filterable card grid with per-category coverage |
| Five peer files | One page: Overview → Visualize → Diagram → Code → Articles |
| A date-sorted pile | Three start-here paths, plus Start here / Building / Deeper on every card |

Deep links work per session and per tab: `#2026-08-19`, `#2026-08-19/visualize`,
`#2026-08-19/code`. Paths and levels are shareable too: `#path/tools`, `#path/how-it-works`,
`#level/start-here`.

Keyboard: `/` search · `j`/`k` or `↑`/`↓` move · `Enter` open · `Esc` back ·
`1`–`5` switch tabs · `[`/`]` older/newer session.

## Commands

```bash
make serve     # build + preview at http://127.0.0.1:8000
make build     # regenerate site/data/ only
make check     # lint every session, write nothing
make deploy    # build and publish to Cloudflare Pages + gh-pages
make clean     # drop site/ and the run cache

make serve NORUN=1   # skip executing the examples (~45s faster, no output pane)
```

A first build runs every Python example; results are cached by source hash in
`.build-cache.json`, so later builds re-run only what changed. An example that
crashes is not a build failure — the reader shows its traceback and the command
to reproduce it locally.

## Categories

Eleven categories in three **weighted tiers**, always with a practical
software-engineering angle. The tier is about how far a topic sits from the
reader's Monday morning — not how sophisticated it is. A Tier A topic can be
every bit as deep; it just starts from a problem the reader already has.

Selection is weighted, not a flat cycle: an equal 1-of-11 rotation meant the
single most relevant category (Coding Agents & Productivity) appeared **once**
in the first 20 sessions, tied for last, while GPU quantization and diffusion
sampling each got double.

**Tier A — ship it this week (~50%)**
1. Coding Agents & Productivity — *operating* the tools you already use: Claude
   Code / Cursor / Codex / Gemini CLI config, hooks, skills, subagents, MCP
   setup, context and cost management, and what their changelogs shipped
2. Building Agents & MCP — *authoring* agent systems: tool schemas, MCP servers,
   orchestration, SDKs
3. AI Engineering Practices — reviewing, testing and trusting agent-written code
4. Evals & Reliability — "does my AI feature actually work?" App-level harnesses,
   guardrails you ship, regression catching

**Tier B — understand the machine (~30%)**
5. New Models & APIs
6. AI in Production
7. Hands-on Techniques — fine-tuning, RAG, prompt & context engineering

**Tier C — frontier (~20%)**
8. Applied Research
9. AI Hardware for Engineers — how to *use* the hardware you have or rent
   (instance choice, quantization you can run, memory ceilings), not novel silicon
10. Multimodal Engineering
11. AI Safety & Alignment

Every session — including Tier C — carries a **What This Means for You** section:
when it matters, how it affects you, and what to actually do about it.

## Running a session manually

Two skills, same session workflow — they differ only in whether the result leaves your machine.

| Skill | Writes to `~/ai_learning/` | Pushes here | Updates the site |
|---|---|---|---|
| `/ai-daily-learn` | yes | **no** — local only | no (`make serve` to preview) |
| `/ai-daily-learn-publish` | yes | yes, straight to `main`, no PR | yes |

```
/ai-daily-learn                              # local only, next category in the rotation
/ai-daily-learn "speculative decoding"       # local only, your topic

/ai-daily-learn-publish                      # local + push + deploy
/ai-daily-learn-publish "speculative decoding"
```

The 11:00 job runs the publishing variant. To publish a session you generated locally earlier,
just run `/ai-daily-learn-publish` and ask it to publish that date — it skips regeneration when
the session already exists on disk.

## Adding a session by hand

Create `YYYY-MM-DD/` with any of the five files and add a `journal.md` block.
`topic.md` must start with an `# H1` title followed by `**Key**: value` metadata
lines — `Category` and `Date` drive the grid, and the journal block's
`- **Key insight**:` line becomes the card blurb. Everything else is optional:
sessions missing a visualizer, diagram, or articles file simply show fewer tabs.

`visualize.html` is copied as a standalone artifact and loaded only when its pane opens. The
reader runs it in a script-only sandbox without same-origin, popup, form, storage, or network
access; visualizers therefore keep all CSS, JavaScript, and data inline.

Reading progress lives in `localStorage`, so it is per-browser and never leaves
the machine.
