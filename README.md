# AI Daily Learn

Daily 30-minute AI learning sessions — and the reader that makes them readable.

**Read them here:** https://magna56.github.io/aI_daily_run/

Sessions are generated by the `/ai-daily-learn-publish` Claude Code skill
(bundled in `.claude/skills/`) and pushed here automatically every day at 11:00.

## Layout

```
journal.md          # running index of every session
YYYY-MM-DD/         # one session — the source of truth, never generated from the site
  topic.md          # the technical writeup (~10 min read)
  code_example.py   # runnable, pure Python, no API keys (~15 min)
  diagram.excalidraw# the visual
  articles.md       # 3-5 curated sources with summaries

index.html          # the reader (self-contained: CSS + JS inline, no CDN)
build.js            # session folders -> site/data/
lib/excalidraw-svg.js  # .excalidraw -> SVG, at build time
lib/runner.js       # runs each code_example.py, captures its output
```

A `-s2` suffix (`2026-08-03-s2`) means a second session on the same day.
`site/` is build output: not committed, force-pushed to the `gh-pages` branch.

## The reader

On the GitHub tree view a `.excalidraw` file is an unreadable JSON blob and a
`code_example.py` is something you have to clone before it teaches you anything.
The site fixes exactly that:

| On the tree view | In the reader |
|---|---|
| `.excalidraw` renders as raw JSON | Pre-rendered to SVG, with pan/zoom — original still downloadable |
| `code_example.py` is inert | Executed at build time, so its output sits beside the source |
| No index or search | Searchable, filterable card grid with per-category coverage |
| Four peer files | One page: Overview → Diagram → Code → Articles |

Deep links work per session and per tab: `#2026-08-19`, `#2026-08-19/code`.

Keyboard: `/` search · `j`/`k` or `↑`/`↓` move · `Enter` open · `Esc` back ·
`1`–`4` switch tabs · `[`/`]` older/newer session.

## Commands

```bash
make serve     # build + preview at http://127.0.0.1:8000
make build     # regenerate site/data/ only
make check     # lint every session, write nothing
make deploy    # build and publish to gh-pages
make clean     # drop site/ and the run cache

make serve NORUN=1   # skip executing the examples (~45s faster, no output pane)
```

A first build runs every Python example; results are cached by source hash in
`.build-cache.json`, so later builds re-run only what changed. An example that
crashes is not a build failure — the reader shows its traceback and the command
to reproduce it locally.

## Running a session manually

Two skills, same session workflow — they differ only in whether the result leaves your machine.

| Skill | Writes to `~/ai_learning/` | Pushes here | Updates the site |
|---|---|---|---|
| `/ai-daily-learn` | yes | **no** — local only | no (`make serve` to preview) |
| `/ai-daily-learn-publish` | yes | yes, straight to `main`, no PR | yes |

```
/ai-daily-learn                              # local only, next category in the rotation
/ai-daily-learn "speculative decoding"       # local only, your topic

/ai-daily-learn-publish                      # local + push + deploy
/ai-daily-learn-publish "speculative decoding"
```

The 11:00 job runs the publishing variant. To publish a session you generated locally earlier,
just run `/ai-daily-learn-publish` and ask it to publish that date — it skips regeneration when
the session already exists on disk.

## Adding a session by hand

Create `YYYY-MM-DD/` with any of the four files and add a `journal.md` block.
`topic.md` must start with an `# H1` title followed by `**Key**: value` metadata
lines — `Category` and `Date` drive the grid, and the journal block's
`- **Key insight**:` line becomes the card blurb. Everything else is optional:
sessions missing a diagram or an articles file simply show fewer tabs.

Reading progress lives in `localStorage`, so it is per-browser and never leaves
the machine.
